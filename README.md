# SIP Оператор — веб-клиент

Веб-интерфейс оператора для звонков: регистрация/подключение к АТС, исходящие
звонки, приём входящих, история звонков ("Мои звонки"). Чистый HTML/CSS/JS без
фреймворков на фронтенде.

Поддерживаются **два независимых режима работы**, переключаются в настройках
(шестерёнка):

- **AMI-режим** (по умолчанию) — браузер общается с небольшим Node.js-бэкендом
  (`server/`), который держит подключение к Asterisk Manager Interface (AMI).
  Оператор нажимает «Позвонить» → Asterisk сам звонит на его SIP-телефон
  (например, MicroSIP) → как только оператор поднимает трубку, Asterisk
  соединяет его с абонентом. Разговор идёт на обычном телефоне/софтфоне,
  браузер только управляет звонком и показывает статус/список звонков. Не
  требует никаких изменений на самом Asterisk — работает "из коробки", если
  AMI доступен.
- **WebRTC-режим** — прямой звонок в браузере по SIP/WebSocket через
  [JsSIP](https://jssip.net/), голос идёт прямо во вкладке. Требует, чтобы на
  Asterisk был включён `ws`/`wss`-транспорт и WebRTC (ICE/DTLS-SRTP) для
  добавочного номера — это настройка на стороне PBX, отдельная от AMI.

## Структура проекта

```
index.html                главная страница (разметка окна оператора)
css/style.css              стили
js/app.js                  вся фронтенд-логика: оба режима, история, настройки
vendor/jssip.bundle.min.js браузерная сборка JsSIP (используется в WebRTC-режиме)
build/                     вспомогательные файлы для пересборки vendor-бандла
server/                    backend для AMI-режима (Node.js)
  src/ami-client.js          сырой TCP-клиент Asterisk Manager Interface
  src/call-store.js          сборка "звонков" из событий AMI (Dial/Hangup/Originate)
  src/callflow-client.js     клиент веб-панели CallFlow — только для записей разговоров
  src/index.js               Express + WebSocket сервер, отдаёт API браузеру
  .env.example                образец конфига (без секретов)
  .env                        реальные секреты — НЕ коммитить
```

## Запуск фронтенда

Открывать `index.html` напрямую двойным кликом (`file://`) **нельзя** — в
WebRTC-режиме браузер блокирует доступ к микрофону для страниц не по HTTP(S).
Раздайте папку любым простым веб-сервером:

```bash
npx http-server -p 8080
# или
python -m http.server 8080
```

Открыть `http://localhost:8080/`.

## Запуск backend (для AMI-режима)

```bash
cd server
npm install
cp .env.example .env      # затем заполнить реальными значениями
npm start
```

Backend поднимется на `http://localhost:3001` (порт настраивается через
`HTTP_PORT`). В логе должно появиться `[ami] login OK` — подтверждение, что
подключение к Asterisk установлено.

### Настройка `.env`

| Переменная | Назначение |
|---|---|
| `AMI_HOST`, `AMI_PORT` | адрес и порт Asterisk Manager Interface |
| `AMI_USERNAME`, `AMI_SECRET` | учётные данные AMI |
| `AMI_ORIGINATE_CONTEXT`, `AMI_ORIGINATE_PRIORITY` | контекст/приоритет дialplan, через который набирается номер при клике "Позвонить" — **уточните у администратора Asterisk**, какой контекст использует ваш номер для исходящих звонков (значение по умолчанию `from-internal` — частый вариант для FreePBX-подобных систем, но не гарантирован) |
| `AMI_CHANNEL_TECH` | технология канала для набора номера оператора: `SIP` (chan_sip) или `PJSIP` |
| `TRACK_EXTENSIONS` | добавочные номера, для которых собирается общая история звонков (включая звонки, сделанные не через это приложение, например с MicroSIP) |
| `HTTP_PORT` | порт, на котором backend слушает браузер |
| `API_TOKEN` | случайный секрет, которым браузер подтверждает право дёргать API (заголовок `X-Api-Key`, для WebSocket — `?token=`, для `<audio>` — `?key=`) |
| `FRONTEND_ORIGIN` | разрешённый источник для CORS (`*` — только для локальной/LAN разработки) |
| `CALLFLOW_BASE_URL`, `CALLFLOW_USERNAME`, `CALLFLOW_PASSWORD` | отдельная от AMI веб-панель CallFlow (порт 80) — используется только для скачивания записей разговоров (см. ниже). Если не задать — кнопка прослушивания просто вернёт ошибку, остальной функционал не затронут |

**Важно про безопасность:** `AMI_SECRET` даёт полный контроль над АТС
(вызов/сброс любых звонков, прослушивание каналов) — он живёт только в
`server/.env` и никогда не попадает в код, который уходит в браузер. Браузер
общается с бэкендом только через `API_TOKEN`, у которого прав ровно на то, что
явно реализовано в `server/src/index.js` (позвонить/повесить трубку/DTMF/список
звонков). Не публикуйте `server/.env` и не открывайте порт `3001` наружу без
дополнительной защиты (сейчас это простой shared-secret, подходит для
локальной сети, не для интернета).

## Настройка в браузере (шестерёнка в правом верхнем углу)

**AMI-режим:**
- **Адрес backend-сервера** — например `http://localhost:3001`.
- **API-ключ** — значение `API_TOKEN` из `server/.env`.
- **Ваш добавочный номер** — например `101`.

**WebRTC-режим:**
- **WebSocket сервер** — `wss://host:порт/путь` (для Asterisk обычно `8089`).
- **SIP URI**, **Пароль**, **Отображаемое имя**, **STUN/TURN** — как для
  обычного SIP-аккаунта.

Настройки хранятся в `localStorage` браузера (только на этом компьютере).
Флажок «Автоматически подключаться» переподключает выбранный режим при
следующей загрузке страницы.

## Возможности

- **Исходящий звонок** — ввести номер и нажать «Позвонить».
  - AMI-режим: Asterisk звонит вам на телефон, затем на абонента; статус и
    таймер разговора обновляются в реальном времени через WebSocket от backend.
  - WebRTC-режим: звонок идёт напрямую из вкладки браузера.
- **Входящий звонок** — экранное уведомление с номером/именем звонящего.
  - AMI-режим: ответить можно только на самом SIP-телефоне (в браузер нельзя
    передать аудио без WebRTC), но **отклонить** звонок из браузера работает
    по-настоящему (AMI кладёт трубку на входящей линии).
  - WebRTC-режим: «Принять»/«Отклонить» полностью работают из браузера.
- **Во время разговора** — таймер длительности, «Завершить» (оба режима);
  «Микрофон»/«Удержание» и DTMF-клавиатура — в WebRTC-режиме через сам звонок,
  в AMI-режиме DTMF шлётся через backend (`Action: PlayDTMF`), mute/hold
  недоступны (нет локальной медиасессии).
- **Мои звонки** — таблица с направлением, номером, временем, длительностью и
  статусом.
  - WebRTC-режим: только звонки, сделанные из этой вкладки, хранится в
    `localStorage`.
  - AMI-режим: **все** звонки добавочного номера (включая сделанные напрямую с
    телефона/MicroSIP и входящие), источник — журнал backend
    (`server/data/calls.log.jsonl`), не зависит от конкретной вкладки/сессии
    браузера.
- **Прослушивание записи звонка** (только AMI-режим, ▶ рядом со строкой в
  «Мои звонки») — открывает аудиоплеер прямо над таблицей. Работает через
  `CALLFLOW_*` в `server/.env`: backend сам логинится в веб-панель CallFlow
  (отдельная система от AMI, на порту 80), находит нужную запись по Uniqueid
  звонка в её отчёте за нужный день и отдаёт аудио браузеру — сам логин/пароль
  от CallFlow наружу не уходит. Если для звонка нет записи (не дозвонились,
  либо запись не производилась) — плеер покажет «Запись не найдена».

Оба режима поддерживают один активный звонок одновременно.

## Пересборка vendor/jssip.bundle.min.js

Нужно только для WebRTC-режима. Начиная с некоторых версий пакет `jssip` в npm
не публикует готовый браузерный файл — только исходники на CommonJS, поэтому в
`vendor/` лежит собственная сборка через webpack:

```bash
cd build
npm install
npx webpack --config webpack.config.js
```

Это создаст (перезапишет) `vendor/jssip.bundle.min.js`.
